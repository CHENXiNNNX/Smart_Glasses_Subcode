- 采用三级缓冲池架构：
  (1) 第一级：固定大小对象池
    - 音频帧池：预分配100个 2KB 固定块（支持2秒缓冲，总内存200KB）
    - 小视频帧池：预分配50个 32KB 固定块（覆盖常规帧，总内存1.6MB）
    - 大视频帧池：预分配20个 128KB 固定块（覆盖I帧和高质量帧，总内存2.5MB）
    - 特点：零分配开销(O(1),~10ns)，64字节内存对齐(cache line对齐)，无内存碎片
    - 分配策略：无锁双缓冲机制 + 原子索引
  (2) 第二级：动态内存池(Slow Path，处理超大帧或突发情况)
    - 使用已有的MemoryPool类(/app/tool/memory/mem_pool.h)
    - 初始大小2MB，按需自动扩展(扩展因子2.0)
    - 支持对齐分配、自动合并相邻空闲块
    - 分配时间<1μs，适合处理10%的极端情况
  (3) 第三级：零拷贝传输层
    - DMA缓冲区复用：VI/VENC直接使用DMA，CPU不参与数据搬运
    - 引用计数管理：多消费者共享同一帧，避免内存拷贝
    - 环形队列传递：使用指针传递数据，不移动数据本身
    - 内存映射：硬件缓冲区映射到用户空间直接访问
- 具体实现细节：
  (1) 分开实现音视频内存管理(audio_mem_t/video_mem_t)
    - 初始化时预分配所有固定池
    - 实现分配接口：alloc_audio_buffer() / alloc_video_buffer()
    - 自动选择最优分配策略（优先固定池，未命中则动态池）
    - 线程安全：使用原子操作和无锁数据结构
  (2) 帧结构设计
    - 包含引用计数（std::atomic<int>）
    - 包含数据指针、大小、时间戳等元数据
    - 分配时引用计数=1，共享时递增，使用完递减
    - 引用计数归零时自动回收到对应池
  (3) 性能目标
    - 音频分配延迟: <50ns (固定池), <500ns (动态池)
    - 视频分配延迟: <100ns (固定池), <1μs (动态池)
    - 内存碎片率: <5%
    - 固定池命中率: 音频>99%，视频>90%
  (4) 日志集成
    - 使用LOG_DEBUG记录缓冲区分配/释放详情
    - 使用LOG_INFO记录池统计信息(每10秒)
    - 使用LOG_WARN记录固定池未命中情况
    - 使用LOG_ERROR记录内存分配失败
    - 模块标签：[AudioBuffer] / [VideoBuffer] / [MediaPool]
